# Data Model: The Distillation Harness Interface

## Run record (`schemas/run-record.v1.json`)

Strict object; unknown keys are refused. All strings are UTF-8 text.

| Field | Type | Notes |
|---|---|---|
| `id` | string | unique within a session; the command uses the run's label (`001`, ...) |
| `prompt` | string | the task prompt the agent received |
| `models` | `{ requested: string \| null, resolved: string[] }` | canonical `<provider>/<model>` names |
| `settings` | `{ temperature: number \| null, effort: string \| null, thinking: string \| number \| null } \| null` | pinned settings the run recorded |
| `reasoning` | `"returned" \| "partial" \| "none" \| "not-kept"` | whether the turns carry the provider's reasoning; `not-kept` for a run that kept no conversation (its turns are its calls alone) |
| `turns` | `Turn[]` | in order |
| `finalAnswer` | string | the agent's last message |

`Turn`: `{ text: string, reasoning?: string, calls: Call[] }` (`reasoning` absent when the provider returned none).
`Call`: `{ id: string, tool: string, arguments: object, status: "ok" \| "failed", output: string, refusal?: string }`. `output` is the text
the agent saw, regenerated by replay; `refusal` is the world's own refusal text for a failed call.

Excluded and asserted absent by tests: score, reached, solver path or best run, extra calls, goal role, which-calls-were-needed, world
or goals file, any timing (`duration`, `startMs`, ...).

## Skill set (`schemas/skill-set.v1.json`)

| Field | Type | Notes |
|---|---|---|
| `skills` | `Skill[]` (at least 1) | one skill is valid |

`Skill`: `{ name: string (kebab-case), description: string, files: { path: string, content: string }[], tags?: string[], evidence?: { run: string, call?: number }[] }`.
`files` holds a `SKILL.md` with front matter (name, description) and optional references; paths are relative with no `..`; the existing size
limits apply (`LIMITS`: 64 KiB a package, 32 KiB a file).

On disk (`distills/<label>/skills/`): one folder per skill (`<name>/SKILL.md`, `<name>/references/...`) and `skill-set.json` beside the
folders holding each skill's tags and evidence; nothing but the skill's own files inside a folder.

## Harness interface (`src/distill/harness.ts`)

```text
Harness            { name: string; open(experimentId: string, signal: AbortSignal): Promise<Session> }
Session            { record(run: RunRecord, signal): Promise<void>
                     distill(request: DistillRequest, signal): Promise<DistillResult>
                     describe(): Provenance
                     close(): Promise<void> }
DistillRequest     { runIds: string[] (at least 1, all recorded); maxUsd?: number; maxSkills?: number }
DistillResult      { ok: true, skills: SkillSet, stages: Stage[] } | Refusal
Refusal            { ok: false, code: "no_skill" | "spend_limit" | "cancelled" | "failed", spendUsd: number | null, stages: Stage[] }
Stage              { stage: string, durationMs: number, tokens: Tokens | null, costUsd: number | null, model?: { requested: string, resolved: string | null } }
```

State: a session is `open` until `close()`; `record` after `close` is refused; `distill` over an id not recorded is refused without work.

## Provenance (`harness.json`)

| Field | Notes |
|---|---|
| `harness` | `{ name, processVersion }` |
| `roles` | `{ <role>: { requested, resolved: string[], settings: RecordedSettings \| null, price: PriceQuote \| null } }` |
| `prompts` | `{ <kind>: { version, sha256 } }` for each prompt kind the harness used (`review-rubric`, `distiller`) |
| `service` | an external service's `{ name, version, released, commit, environment }`, or `{ name, unknown }`, or null |
| `retainedExternally` | true when run records are kept in a third-party store (NAMS: true, with the option that allowed it; bespoke-one-shot: false, since it only calls a model provider the project already calls) |
| `runs` | each recorded run: `{ id, runLogSha256, scoreSha256, models, settings }`, hashes only |
| `stages` | `Stage[]` |
| `spend` | `{ costUsd: number \| null, pricedStages, unpricedStages, tokens }` |
| `skills` | `{ name, sha256 }[]`, the hash of each skill as written |
| `review` | for a harness that reviews: `{ rounds: [{ n, skillSha256, overall }], outcome }` (hashes and verdicts only, no text) |
| `outcome` | `"skill-set"` or a refusal code, and a fixed `reason` |

It holds hashes, identifiers, settings and fixed codes, never recorded text or a role's free text.

## Cast and summary (read by the report)

- `cast.harness: { name: string, roles: Record<string, { model: string, settings?: Settings }> }`. An older cast (`teacher`, `student`,
  `distiller: { service, critic, reviser }`) is read as the same cast with `harness.name = "nams-reviewed"` and roles `critic` and `reviser`.
- `distillation: { record: string }`: the repository-relative path of a `harness.json` or a legacy `loop.json`.
- `promptSet.distiller?: string`: a pinned version of the distiller prompt.

## Prompt kind

`prompts/distiller/v<N>.txt`: no placeholders, no word check, a changelog section per version; listed by `scripts/prompts.ts`.

## State transitions: a session

```
open ──record*──▶ open ──distill*──▶ open ──close──▶ closed
  any step may fail or be cancelled: the session still closes, releasing what it created
distill: skill set (ok) | refusal (no_skill | spend_limit | cancelled | failed) with the spend so far
```
